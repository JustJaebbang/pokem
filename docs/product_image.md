# 판매상품 이미지 한 장

기존 sell_product_image 문자열 필드에 이미지 주소 하나를 저장합니다. DB 구조 변경은 없습니다.

## 설치

```powershell
pip install -r requirements-images.txt
```

## 앱에서 사용하는 순서

1. `POST /sell_product/image`에 Bearer 토큰과 multipart/form-data의 `file` 필드로 사진 한 장을 보냅니다.
2. 응답의 sell_product_image를 기존 상품 등록 또는 수정 JSON에 그대로 넣습니다.
3. 표시할 때 API 서버의 주소에 이 상대 경로를 붙입니다.

업로드 응답 예:

```json
{"sell_product_image": "/media/products/0123456789abcdef0123456789abcdef.jpg"}
```

예를 들어 API 서버가 `http://192.168.20.43:8000`이면 위 주소 앞에 해당 서버 주소를 붙여 이미지를 표시합니다.
앱은 기기 내부 파일 경로나 base64 문자열을 상품의 이미지 필드로 보내지 않습니다.
상품 등록의 나머지 필드와 API 형식은 그대로 사용합니다. 대리판매 등록의 이미지 필드에도 같은 경로를 사용할 수 있습니다.
상품 등록·수정 API는 기존 외부 이미지 주소도 계속 받을 수 있습니다.
업로드는 로그인한 계정에 허용되며 이미지 조회는 판매상품 조회처럼 공개입니다.

## 검증 및 저장

JPEG·PNG·WebP 정지 이미지만 지원합니다. 입력과 변환 결과는 각각 최대 5MiB, 해상도는 최대 1,000만 픽셀입니다.
확장자·Content-Type 대신 실제 이미지 내용을 검사하고, EXIF 회전을 반영한 뒤 다시 인코딩합니다.
위치정보 등 메타데이터는 저장하지 않습니다. 파일명은 서버에서 UUID로 생성합니다.
빈 파일은 422, 지원하지 않거나 손상된 이미지는 415, 용량·해상도 초과는 413입니다.

파일은 서버 프로젝트의 `uploads/products` 폴더에 저장하고 Git에서는 제외합니다.
다른 머신으로 배포하거나 여러 서버를 사용하면 공유·영속 저장소로 교체해야 합니다.
재배포 시 uploads 폴더를 삭제하면 기존 이미지 주소는 동작하지 않으므로 저장 파일을 보존해야 합니다.
운영 서버에서는 프록시의 요청 본문 크기 제한도 설정해야 합니다. 앱의 5MiB 검사는 multipart 파싱 이후 적용됩니다.

업로드와 상품 저장은 두 요청입니다. 상품 저장 실패나 이미지 교체 시 기존 파일은 자동 삭제하지 않습니다.
현재는 파일을 유지하며, 정리 기능을 추가할 때 DB에서 사용 중인 주소인지 확인한 후 삭제해야 합니다.
