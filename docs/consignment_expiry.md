# 대리판매 2주 만료 반환

`post_consign_item_expires_at`은 등록 시각 + 14일인 한국시간 DATETIME입니다.
기존 등록 건도 등록일 + 14일로 보정했습니다. SQL은 `sql/consignment_expiry.sql`이며 한 번만 적용합니다.

`POST /post_consign_item` 요청에는 매니저가 선택한 `return_delivery_company_code`를 필수로 보냅니다.
기존 필드에 다음을 추가합니다.

```json
{"return_delivery_company_code": "TEST_DELIVERY_001"}
```

목록과 상세 응답에 만료일과 반환 배송업체가 포함됩니다.
기존 건의 배송업체 지정 및 진행 중인 건의 변경은 매니저 권한으로
`PATCH /post_consign_item/{code}/return-company`에 위 본문을 전송합니다.
기존 데이터의 배송업체는 임의로 지정하지 않았으므로 매니저가 지정해야 합니다.

FastAPI lifespan에서 시작 시 및 매 60초마다 만료 건을 확인합니다.
서버가 중단되면 처리는 멈추며 재시작 시 누락된 만료 건을 처리합니다.
실제 구매가 진행 중이거나 거래완료된 상품은 반환하지 않습니다.
스캔 전이라도 만료된 대리판매 상품 구매는 409로 차단합니다.

반환 처리 시 상품은 `반환대기`, 대리판매 의사와 검수 선택은 `반환`으로 바뀝니다.
기존 소유자·검수 물품의 return을 생성하고 등록 매니저를 배정한 뒤,
지정 배송업체로 `배송준비` delivery를 생성합니다. 판매 완료일은 기록하지 않습니다.
이 변경은 하나의 트랜잭션으로 처리하며 배송 생성 실패 시 모두 롤백합니다.
물품별 잠금과 상태 재확인으로 여러 서버·반복 실행에도 중복 생성하지 않습니다.
실패 건은 로그에 남기고 다음 스캔에서 다시 시도합니다.

배송준비 기록 생성은 실제 택배사 발송이나 배송 완료를 뜻하지 않습니다.
배송업체가 지정되지 않은 기존 건은 자동 반환에 실패하므로 수정 API로 업체를 지정해주세요.

`tests/verify_consignment_expiry_db.py`는 실제 DB를 사용해 14일 만료일,
만료 전·거래중·거래완료 제외, 만료 구매 차단, 배송 실패 롤백,
소유자·검수·업체 연결, 중복 방지를 확인한 뒤 테스트 데이터를 롤백합니다.
