# 검수 보증금 환급

`POST /deposit_refund`는 관리자 권한으로 환급 내역만 기록합니다.
실제 송금·포켐머니 잔액 변경·결제 상태 변경은 수행하지 않습니다.

```json
{
  "pay_pay_no": "결제번호",
  "manager_manager_id": "담당자ID"
}
```

담당자는 로그인한 본인 ID를 사용하며 생략하면 토큰에서 결정합니다.
사용자 ID와 `deposit_refund_price`는 요청에 받지 않습니다.
환급 대상 사용자는 결제에서 가져오며, 금액 필드를 전달하면 422입니다.

결제완료된 검수비에 연결된 신청의 검수 카드만 계산합니다.
`inspect_status=검수완료`이고 비어 있지 않은 등급이 `FAKE`가 아닌 카드당 5,000원입니다.
FAKE는 앞뒤 공백과 대소문자를 정규화해 비교합니다.
검수대기·검수중·등급 누락·FAKE 카드는 제외합니다.

이번 환급액 = 현재 환급 가능한 카드 수 × 5,000원 − 해당 결제의 기존 환급 총액.
카드가 나눠서 검수완료되어도 미환급분만 추가 기록합니다.
새 환급액이 없으면 409이며 0원 환급 기록은 만들지 않습니다.
누적 환급 가능액이 결제 금액이나 DB INT 한도를 넘으면 409입니다.
기존 환급 금액이 누락·비정상이면 자동 보정하지 않고 확인을 요구합니다.

결제 행을 FOR UPDATE로 잠가 같은 결제의 환급 요청을 직렬화하고,
검수 카드와 기존 환급 내역을 확인한 뒤 삽입·커밋합니다. 오류 시 전체 롤백합니다.
등급 판정 자체가 이 API를 자동 호출하지는 않으며 담당자가 검수완료 후 환급을 요청합니다.
환급번호는 결제번호 + YYYYMMDDHHMMSSffffff로 생성해 같은 날 추가 환급도 기록합니다.
최대 길이는 84자로 기존 85자 한도 안이며 테이블 변경은 없습니다.

조회 API는 기존과 같습니다. 테스트 중 실제 DB에 환급 기록을 생성하지 않았습니다.

GET /deposit_refund?pay_no=결제번호로 결제별 조회가 가능합니다. 사용자 요청에는 본인 필터가 항상 함께 적용되며 기존 limit/offset을 유지합니다.
