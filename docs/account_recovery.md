# 이메일로 계정 찾기

일반 사용자 계정만 지원합니다. 로그인 화면의 아이디 / 비밀번호 찾기에서 가입 이메일로 인증번호를 받아 아이디를 조회하거나 비밀번호를 변경합니다. 담당자·책임자 계정은 대상이 아닙니다.

## 서버 설정

`.env.example`의 SMTP 항목을 복사해 **로컬 `.env`**에 입력합니다. 비밀 값은 Git에 올리지 않습니다.

- `SMTP_HOST`: 메일 제공자의 SMTP 서버
- `SMTP_PORT`: 보통 STARTTLS 587 또는 SSL 465
- `SMTP_SECURITY`: `starttls` 또는 `ssl` (평문 전송 미지원)
- `SMTP_FROM`: 제공자가 허용한 발신 주소
- `SMTP_USERNAME`, `SMTP_PASSWORD`: 발송 계정과 앱 비밀번호 등 제공자가 발급한 인증 정보

환경변수를 반영하려면 API 서버를 재시작합니다. 설정이 없으면 503을 반환하며 메일 발송을 성공한 것처럼 처리하거나 인증번호를 화면·응답·로그에 출력하지 않습니다. 추가 Python 패키지나 DB 마이그레이션은 없습니다.

## API

`POST /auth/recovery/request`

```json
{"purpose":"find_id","email":"가입 이메일"}
```

비밀번호 재설정은 `purpose=reset_password`와 `user_id`를 함께 보냅니다. 응답은 `challenge_id`, `expires_in=300`, `retry_after=60`, 공통 안내문입니다. 가입 여부나 아이디는 발송 요청 응답에 포함하지 않습니다. 일치하는 활성 계정이 있는 경우에만 메일을 보냅니다.

`POST /auth/recovery/complete`

```json
{"challenge_id":"요청 응답의 값","code":"메일로 받은 6자리"}
```

아이디 찾기는 인증 후 `user_ids`를 반환합니다. 비밀번호 재설정은 `new_password`(8~128자)를 추가하며 Argon2로 해시해 저장합니다. 처리 후 인증번호를 폐기하며 자동 로그인하지 않습니다. 새 비밀번호로 로그인합니다.

## 제한과 운영 범위

- 이메일당 발송 요청 간격 60초, 시간당 5회. 클라이언트 IP당 시간당 20회. IP는 직접 연결 주소를 사용하며 임의의 전달 헤더를 신뢰하지 않습니다. 프록시 뒤에서는 프록시 IP를 공유하므로 운영 시 신뢰할 프록시 구성을 별도로 확인합니다.
- 인증번호 유효 시간 5분, 최대 5회 입력, 처리 성공 시 일회용 소진. 이메일·IP·인증번호 비교 값은 HMAC으로 보관하며 인증번호 평문을 저장하지 않습니다. 대상 이메일은 서버 메모리에 보관하며 만료된 요청은 다음 발급 요청 때 정리합니다. 만료 후 인증은 즉시 거부합니다.
- 탈퇴 계정은 제외합니다. 발급 후 이메일·비밀번호가 바뀌거나 탈퇴하면 기존 인증번호로 복구할 수 없습니다.
- 현재 WebSocket 서버의 **단일 프로세스/worker 운영**을 전제로 메모리에서 인증번호와 요청 제한을 관리합니다. 서버 재시작 시 번호와 제한 기록이 사라지므로 다시 발급해야 합니다. 여러 worker·서버를 사용할 경우 Redis 등 공용 저장소로 이전해야 합니다. 각 worker에 별도 메모리를 둔 채 확장하지 않습니다.
- 별도 DB 컬럼·테이블은 추가하지 않습니다. 비밀번호 재설정 성공 시에만 기존 `user_password`를 변경합니다.
- 기존에 발급된 액세스 토큰을 강제로 폐기하지 않습니다. 이미 로그인한 기기의 토큰은 기존 만료 시간까지 유효할 수 있습니다. 모든 기기 강제 로그아웃에는 별도의 토큰 버전·폐기 기능이 필요합니다.
- 비밀번호 변경 응답이 유실되면 앱은 변경 여부를 단정하지 않고 새 비밀번호로 로그인해 확인하도록 안내합니다.

## 확인한 범위

발송기는 모의 SMTP로 TLS·메일 구성을 검증했습니다. DB 테스트는 격리된 SQLite에서 수행하며 실제 사용자 비밀번호를 변경하거나 실제 메일을 발송하지 않습니다. 실제 발송 확인에는 SMTP 설정 후 본인의 테스트 계정과 수신함을 이용해야 합니다.
