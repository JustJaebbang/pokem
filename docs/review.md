# 구매확정 후 리뷰 작성

현재 연결된 DB에는 `sql/review_purchase.sql`을 적용했습니다. 구매 코드 외래 키와 UNIQUE 제약, review_code VARCHAR(66)을 확인했습니다.
새 DB에서 구성할 때 필요한 SQL이며, 이미 적용한 DB에서 반복 실행할 필요는 없습니다. 기존 데이터가 있는 다른 DB는 구매 코드 매핑 후 마이그레이션해야 합니다.

구매자 로그인 → 충전 → 구매 → 구매확정 → `POST /review` 순서로 진행합니다.

```json
{
  "purchase_item_purchase_item_code": "구매코드",
  "review_rating": 5,
  "review_contents": "상품 잘 받았습니다."
}
```

평점은 정수 1~5, 내용은 공백만 아닌 1~500자입니다.
작성자·상품·작성일은 서버에서 결정합니다. 클라이언트가 임의로 보내면 422입니다.
로그인한 구매자의 거래인지 확인하고 해당 판매등록에 완료일이 있을 때만 저장합니다.
리뷰 기본키 이름은 `review_code`이며 값은 `구매코드_작성일시`로 생성합니다.
한국 시간 `%Y%m%d%H%M%S%f`를 사용하며 코드 최대 길이는 66자입니다.
구매 코드의 UNIQUE 제약과 거래 행 잠금으로 구매 한 건당 리뷰 한 개를 보장합니다.
작성자가 아니면 403, 미확정·이미 리뷰가 있는 거래면 409입니다.

- `GET /review`: 전체 리뷰 공개 조회
- `GET /review?sell_product_code=상품코드`: 상품별 리뷰 공개 조회
- `GET /review/{review_code}`: 리뷰 상세 공개 조회

이번 구현은 작성·조회이며 수정·삭제는 포함하지 않습니다.
