# 태블릿 관리자 화면

기존 `main.dart`의 ProviderScope와 로그인/회원가입/세션 복원 기능을 재사용합니다.
로그인 응답의 `role`이 `manager`이면 관리자 메인으로, `user`이면 기존 고객 화면으로 이동합니다.
최초 매니저 계정은 서버 운영 절차로 준비하며 일반 회원가입에서 관리자 권한을 선택하지 않습니다.

## 구조

- `lib/model/manager`: 검수신청·검수상품·대리판매 응답 모델
- `lib/service/manager`: Bearer 토큰을 포함하는 HTTP 요청 및 오류 처리
- `lib/repository/manager`: 세 목록을 병렬 조회해 대시보드 구성
- `lib/vm/manager`: Riverpod Notifier로 로딩·검색·상태 필터·선택·변경 처리 관리
- `lib/view/manager`: 태블릿 대응 매니저 화면과 입력 폼

DB는 기존 FastAPI를 통해 접근합니다. Flutter에서 DB에 직접 접속하지 않습니다.

## 제공 기능

- 검수신청/검수대기/검수중/검수완료 건수: 서버 목록 전체 기준
- 검수신청 검색, 상세 조회, 실물 검수상품 등록
- 검수상품 검색 및 상태 필터, 검수 시작, 등급·사유 입력 후 완료
- 대리판매 등록 내역 및 거래 완료 여부 조회
- 로딩/빈 목록/서버 오류/재시도, 처리 중 중복 제출 방지
- 1000 logical pixels 이상: 메뉴 + 목록 + 상세 패널
- 720~999: 메뉴 + 목록, 상세는 하단 시트
- 720 미만: 하단 메뉴 + 목록, 상세는 하단 시트

기존 `/inspection_request`, `/inspect`, `/post_consign_item` GET 및
`/inspect`, `/inspect/{code}/start`, `/inspect/{code}/complete` POST를 사용합니다.
변경 성공 후 목록을 다시 조회하며, 재조회 실패는 쓰기 실패와 구분해 표시합니다.
타임아웃에는 처리 여부를 새로고침으로 확인해야 합니다.

## 실행 및 검증

```powershell
flutter run --dart-define=API_BASE_URL=http://192.168.0.5:8000
flutter analyze
flutter test
```

실제 태블릿에서는 기기에서 접근 가능한 서버 IP를 지정합니다.
현재 기본 주소 `192.168.0.5`는 개발 PC의 Wi-Fi 주소입니다. IP가 바뀌면 `API_BASE_URL`로 다시 지정합니다.
Android 에뮬레이터에서는 `http://10.0.2.2:8000`을 사용합니다.
HTTP Mock 기반으로 인증 헤더·검수 상태 변경·입력 검증·오류 및 태블릿 크기를 검증합니다.
실제 서버/DB 통합 검증은 별도로 필요합니다.

## 현재 범위

대리판매 신규 등록, 검수신청 매니저 배정/검수비 확정, 배송/반환 처리는 포함하지 않습니다.
디렉터 계정은 기존 세션 화면을 유지합니다. 현재 서버의 검수/대리판매 목록 서비스가
매니저 이외 역할에 `user_id`를 참조하고, 일부 변경 라우트는 `manager_id`를 직접
참조하므로 디렉터를 연결하기 전에 담당 매니저 지정과 권한 처리를 정리해야 합니다.
